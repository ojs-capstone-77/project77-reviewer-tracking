# Contributing

## Branching

Use the format `type/short-description` for branch names.

All work is done on a branch. Never commit directly to `main`. All changes are merged back into `main` through a pull request.

## Commit Messages

This project uses [Conventional Commits](https://www.conventionalcommits.org/).

Format: `type: short description`

- `feat` – new feature
- `fix` – bug fix
- `docs` – documentation only
- `chore` – maintenance, config, dependencies
- `refactor` – code change that doesn't fix a bug or add a feature
- `test` – adding or updating tests

## Pull Requests

1. Create a branch from `main`
2. Do your work and push the branch
3. Open a pull request against `main`
4. Fill out the pull request template
5. Request the PM as a reviewer
6. Address any review feedback
7. Once approved, the PM merges the PR
